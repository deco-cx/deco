# deco on Cloudflare Workers (workerd)

Experimental. These helpers let an existing Fresh + deco site run inside a
Cloudflare Worker without rewriting it. The site is bundled with `deno bundle`
and runs on workerd with `nodejs_compat`.

## Opt in from a site

A site opts in with a `wrangler.jsonc` and two tasks. Nothing changes for the
Deno deploy.

```jsonc
// deno.json
"tasks": {
  "worker:build": "deno eval 'import \"@deco/deco/scripts/workerd\"' -- build",
  "worker:dev": "deno eval 'import \"@deco/deco/scripts/workerd\"' -- dev"
}
```

```sh
deno eval 'import "@deco/deco/scripts/workerd"' -- init  # writes wrangler.jsonc
deno task build          # Fresh snapshot in _fresh/
deno task worker:build   # dist/worker (needs Deno >= 2.4 for `deno bundle`)
deno task worker:dev     # wrangler dev
npx wrangler deploy
```

`scripts/workerd.ts build` also generates the editor's static schemas
(`genSchemas`, the expensive part of `/deco/meta`, which parses the site's
TypeScript) and embeds them; the Worker serves `/deco/meta` and `/live/_meta`
from them (`DECO_SCHEMAS_FILE`), plus the saved blocks of the current decofile.
`init` writes a config with `workers_dev: false`: a `*.workers.dev` URL bypasses
the zone WAF that blocks `/.decofile` and `/deco/meta`.

`scripts/workerd.ts build` generates the Worker entry and app in
`dist/worker/src`, bundles them, and copies `static/` and the Fresh islands to
`dist/worker/assets` (with a `_headers` rule that caches the islands,
`/_frsh/js/<build id>/*`, for a year). It also embeds `.deco/blocks`, the Fresh
snapshot and `deno.json` for the shim's file system. `--no-minify` keeps the
bundle readable. `DECO_LINK=/path/to/deco` bundles against a local deco
checkout.

## Site middleware on static files

Workers Static Assets answers `static/` files before the Worker runs, so a
site's `routes/_middleware.ts` does not see them (on Deno it does). To run the
middleware first for some paths, list them in the site's `wrangler.jsonc`:

```jsonc
"assets": {
  "directory": "dist/worker/assets",
  "binding": "ASSETS",
  "run_worker_first": ["/.well-known/*"]
}
```

Those requests reach the Worker, go through the middleware and are then served
by Fresh, which reads the file from the `ASSETS` binding (`createWorker`'s
`lazyFiles`, an index of the assets generated by the build; island bundles
included, so `/_frsh/*` can be listed too). Keep the list short: every listed
request runs the Worker.

## What each piece does

- `installDenoShim({ env, files, cwd })` installs a `globalThis.Deno` backed by
  the Worker env (string bindings only) and an in-memory, read-only file system
  (`files`). Writes go to an ephemeral overlay, but `Deno.permissions` reports
  `write` as denied, so a disk cache (`WEB_CACHE_ENGINE=FILE_SYSTEM`) falls back
  to the Cache API instead of filling the isolate's memory. Subprocesses,
  `Deno.serve`, KV and cron throw `Deno.errors.NotSupported`.
  `Deno.upgradeWebSocket` uses `WebSocketPair`.
- `keepCacheWritesAlive()` wraps `caches.open()` so `put`/`delete` join the
  current request's `waitUntil`. deco writes loader results without awaiting
  them; without this, workerd cancels the write when the response is sent and
  later hits read truncated JSON.
- `runWithExecutionContext(ctx, fn)` / `waitUntil(promise)` keep background work
  alive for the current request.
- `createWorker({ files, boot })` is the Worker module the build generates; it
  wires the pieces above and sets `DENO_DEPLOYMENT_ID` when it is missing or
  empty (from `BUILD_HASH`, else `workerd`), so deco runs in deploy mode
  (`isDeploy`, platform `cloudflare`). `freshForWorkerd(manifest, config)`
  points Fresh at the shim's file system and registers plugin islands
  statically.

## Constraints a site bundle has to respect

- workerd runs every module body in "global scope", where timers, random values
  and I/O are forbidden, even for modules imported lazily. Fresh, deco and the
  apps do all three at module level, so the site bundle has to be wrapped so its
  body runs inside a request (`wrapInBoot` in `scripts/workerd.ts`).
- `import.meta.url` is undefined on workerd; replace it at build time.
- There is no `window` global (Deno 1.x aliases it to `globalThis`, but hides it
  from npm packages). Server code must use `globalThis.location?.x` instead of
  `window.location?.x`; aliasing `window` globally makes npm packages such as
  `brotli` take their browser path and crash.
- Do not use `--keep-names`: esbuild then injects `__name()` into functions that
  deco serializes to the browser.
- Code must not rely on `Function.prototype.name` (bundlers rename functions).
  This change fixes the places in the engine that did.
- WebAssembly cannot be compiled from bytes at runtime. Modules that do it at
  load time (e.g. lz4 in the Redis cache) must load it lazily.

## Not supported yet

- `/live/inspect/:block` and `/deco/inspect/:block` (read block sources).
- Background revalidation (`stale-while-revalidate`) runs outside the request
  that triggered it and may be cut short.
- Redis loader cache (`ioredis` needs TCP sockets).
